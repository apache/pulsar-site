Spring Pulsar Has a New Home: Apache Pulsar support for Spring

Lari Hotari
November 10, 2026 · 6 min read

Spring for Apache Pulsar, also known as Spring Pulsar, has a new home in the Apache Pulsar project. Development continues as Apache Pulsar support for Spring, a subproject of Apache Pulsar at the Apache Software Foundation, in the apache/pulsar-spring repository.

The first release, 3.0.0-M1, is available on Maven Central with new Maven coordinates, and the migration guide describes what to change in your application. The Spring team has published its own announcement of the move.

What's happening​

Three pieces of Apache Pulsar integration for Spring used to live in three separate repositories. They now live together in one, apache/pulsar-spring:

Previous repositoryCode
spring-projects/spring-pulsarSpring Pulsar libraries
spring-projects/spring-bootSpring Boot's Apache Pulsar starter and auto-configuration
spring-cloud/spring-cloud-streamSpring Cloud Stream's Apache Pulsar binder

Spring for Apache Pulsar 2.0.8 is the final release from the Spring team. From now on, development, bug fixes, support and releases happen in the Apache Pulsar project.

Why Apache Pulsar is the right home​

The Spring integration depends closely on the Pulsar client, so it's a natural part of the Pulsar project. Developing it alongside the broker and the client libraries keeps it aligned with Pulsar as Pulsar evolves. The first release already shows this, as it moves to the Pulsar 5.0 client. This client is fully compatible with older Pulsar broker versions, so you can switch to the new library without upgrading your brokers.

The subproject follows the same open governance as the rest of Apache Pulsar. Discussion happens on the dev@pulsar.apache.org mailing list, changes go through GitHub issues and pull requests, and the Pulsar PMC votes on releases.

What this means if you use Spring Pulsar​

  • Nothing breaks today. Your applications can keep using 2.0.8 while you plan the move.
  • Plan your move. Version 2.0.8 won't get further updates from the Spring team, so future fixes and features will be in the new artifacts.
  • Try 3.0.0-M1. It's a milestone release, and your feedback will help us shape the 3.0.0 release.

We chose 3.0.0 rather than 1.0.0 for the version to make it clear that this continues from Spring Pulsar 2.x.

What changes​

The migration guide has the details, including the changes for your tests. These are the main ones:

Maven coordinates. All artifacts now use the org.apache.pulsar group ID:

PreviousNew
org.springframework.pulsar:spring-pulsarorg.apache.pulsar:pulsar-spring
org.springframework.pulsar:spring-pulsar-bomorg.apache.pulsar:pulsar-spring-bom
org.springframework.pulsar:spring-pulsar-testorg.apache.pulsar:pulsar-spring-test
org.springframework.boot:spring-boot-pulsarorg.apache.pulsar:pulsar-spring-boot-autoconfigure
org.springframework.boot:spring-boot-starter-pulsarorg.apache.pulsar:pulsar-spring-boot-starter
org.springframework.boot:spring-boot-starter-pulsar-testorg.apache.pulsar:pulsar-spring-boot-starter-test
org.springframework.cloud:spring-cloud-stream-binder-pulsarorg.apache.pulsar:pulsar-spring-cloud-stream-binder

Replace the previous dependencies rather than adding the new ones next to them, so that the previous auto-configuration and binder aren't also on the classpath.

Java packages.

PreviousNew
org.springframework.pulsarorg.apache.pulsar.spring
org.springframework.boot.pulsarorg.apache.pulsar.spring.boot
org.springframework.cloud.stream.binder.pulsarorg.apache.pulsar.spring.cloud.stream.binder

Versions. Spring Boot doesn't manage the version of the new artifacts, so declare it on each dependency or import pulsar-spring-bom. Spring Boot applications must also set the pulsar.version property, since Spring Boot manages an older version of Pulsar, and we recommend setting netty.version too:

<properties>
    <pulsar.version>5.0.1</pulsar.version>
    <netty.version>4.2.20.Final</netty.version>
</properties>

<dependencies>
    <dependency>
        <groupId>org.apache.pulsar</groupId>
        <artifactId>pulsar-spring-boot-starter</artifactId>
        <version>3.0.0-M1</version>
    </dependency>
</dependencies>

The Quick Tour shows the same for Gradle, along with a complete application.

Pulsar client. 3.0.0-M1 requires the Pulsar 5.0.x client, which is fully compatible with older Pulsar broker versions, so you don't need to upgrade your cluster. It uses the unshaded client artifacts rather than pulsar-client-all, so libraries such as Netty and Jackson are now regular dependencies of your application, and the classes in org.apache.pulsar.shade are no longer available. This release doesn't add specific support for the new Pulsar v5 client API yet. See the version compatibility and the Pulsar client requirements for more.

What stays the same​

PulsarTemplate, @PulsarListener, @PulsarReader, the Spring Boot auto-configuration and the Spring Cloud Stream binder all carry over. The spring.pulsar.* and spring.cloud.stream.pulsar.* configuration properties haven't changed. The project remains open source under the Apache License, Version 2.0.

Get involved​

Please try 3.0.0-M1 and tell us how it goes. Report bugs and enhancement requests in GitHub issues, and see the contributing guide if you'd like to work on the code. You can reach the community through the Pulsar discussion channels.

Thank you​

We're grateful to the Spring team for creating this project and for supporting its move to Apache Pulsar, in particular to Soby Chacko, Jason Konicki, Michael Minella and Chris Bono, and to everyone who has contributed to, tested and used Spring Pulsar. Chris Bono also did much of the groundwork for the migration, including the conversion of the source code's Git history and the package migration. We look forward to continuing this work with you.
